# 裁切框选需求

- 日期：2026-07-07
- 关联文档：`2026-07-06-development-progress.md`（5.7 节）、`-technical-design.md`（第 5 节 裁切模型）
- 本文档目的：**记录用户发现的裁切功能不足，定义框选需求**。本文只定义问题和期望，不给方案——方案由高级工程师评估后另出文档（如 `2026-07-07-crop-box-select-solution.md`）。

---

## 0. 背景

当前裁切模型（技术设计第 5 节）的核心操作是**分列 + 横切**：

1. **分列**：用竖向分隔线把页面分成 1-3 列（`column_dividers.x_ratio`）
2. **横切**：在每列内点击落横向刀（`cut_lines.y_ratio`），把列切成纵向片段

`deriveSegments` 纯函数从分列 + 横切推导出矩形片段，每个片段是 `(col_index, x_start_ratio, x_end_ratio, y_start_ratio, y_end_ratio)` 的矩形区域。

这个模型在**规整排版**的试卷上工作良好：题目纵向排列，一列一道或几道，横切即可分隔。但实际试卷有两种常见场景无法处理：

---

## 1. 场景 A：侧边无关区域（姓名栏/考号栏/装订线）

### 现状

很多试卷左侧或右侧有姓名栏、考号栏、装订线等区域，与题目无关，需要排除。当前分列只能画**整页高度的竖线**，无法只排除某一部分——要么整列都排除（但那列里可能有题目），要么不排除（姓名栏会和题目混在一起）。

### 具体例子

```
┌──────────┬─────────────────────────┐
│ 姓名     │  第1题                   │
│ ________ │  ...                     │
│          │                          │
│ 考号     │  第2题                   │
│ ________ │  ...                     │
│          │                          │
│ 班级     │  第3题                   │
│ ________ │  ...                     │
└──────────┴─────────────────────────┘
```

用户想：排除左侧姓名栏，保留右侧题目。但分列后左列是整页高度，里面既有姓名栏也有空白的题目区域——无法只切掉姓名栏。

### 期望

能**框选一个矩形区域标记为"排除"**，该区域不产生片段。或等效地：能画**不贯穿整页高度的竖向分隔**，只排除局部区域。

---

## 2. 场景 B：同一行并排两道题

### 现状

排版不好的试卷，同一行可能有两道题并排（特别是选择题）：

```
┌──────────────────────────────────────┐
│  1. A B C D    2. A B C D            │
│                                      │
│  3. A B C D    4. A B C D            │
│                                      │
│  5. 填空题_______                     │
└──────────────────────────────────────┘
```

当前横切只能按**整行宽度**切割——切第1-2题之间时，刀从左到右贯穿整页，把上面两道题切成一整条。无法把第1题和第2题分开。

分列也无法解决：第1-4题是两列并排，但第5题又是单列宽——分列是**整页统一**的，不能某行双列某行单列。

### 期望

能**在同一行内画竖线把两道并排题分开**。或等效地：能**框选每个题目区域**作为独立片段。

---

## 3. 需求抽象

两个场景归结为同一个核心需求：**需要矩形框选能力**，而不只是"分列+横切"的行列式切割。

具体来说，用户需要：

1. **排除框**：在页面上画一个矩形，标记为"排除区域"——该区域不产生片段（场景 A：排除姓名栏）
2. **分割框**：在页面上画一个矩形，直接定义一个片段的边界——不再依赖分列+横切推导（场景 B：框出并排的每道题）

或者说，当前的裁切模型是**声明式的**（画线→推导片段），框选是**命令式的**（画框→直接定义片段）。两种模式需要共存。

---

## 4. 当前裁切架构（供方案设计参考）

### 数据模型

- `column_dividers`：`(page_id, x_ratio)` — 竖向分隔线
- `cut_lines`：`(page_id, col_index, y_ratio)` — 横向切刀
- `segments`：由 `deriveSegments` 从上两者推导，字段 `(x_start_ratio, x_end_ratio, y_start_ratio, y_end_ratio, col_index, order_index)` — 比例坐标矩形

### 交互层

- `CropOverlay.tsx`：覆盖在 `PDFViewer` 上的 React 层，处理分隔线拖拽、横切落刀
- `useCropData.ts`：加载+变更持久化 hook，调 IPC 写库再更新 state
- 分隔线和横切线的坐标都是比例坐标（0..1），与缩放解耦

### 关键约束

- **比例坐标**：所有坐标都是 0..1 的比例值，与 DPI/缩放无关
- **`deriveSegments` 纯函数**：从分列+横切推导片段列表，10 个单测覆盖
- **撤销**：横切线按 `created_seq` 撤销（最新的一刀先撤）
- **逐页列模式**：每页可独立设列模式

## 6. 红线提醒（方案设计时必须遵守）

- **比例坐标体系不能动**：新功能的所有坐标也必须是比例值（0..1），与缩放/DPI 解耦。
- **`deriveSegments` 纯函数不可破坏**：10 个单测覆盖，框选模式可以是独立的推导逻辑，但不能让原有分列+横切推导退化。
- **裁切→后期处理→入库的数据链不能断**：框选产出的 segments 必须与现有 segments 同构（`x_start_ratio` 等），下游 `renderPageRegion`/`renderSegmentsAtDpi`/`composeQuestionCanvas` 无需改动。
- **先写库再 state（A12）**：框选操作也必须走 IPC 写库再更新 state。
- **入库题号排序**：`derivePreviewQuestions` 和 `handleFinalize` 的 `(page_index, order_index)` 排序不受影响——segments 表结构不变。
- **横切与框选共存**：用户可能在同一页混用——横切处理规整区域，框选处理不规则区域。两种模式不能互斥。

---

## 7. 一句话总结

当前裁切只有分列+横切（声明式行列切割），无法处理侧边姓名栏排除（需要局部排除矩形）和同行并排题分割（需要行内竖向分割或直接框选定义片段）。核心需求是增加**矩形框选**能力（排除框 + 分割框），与现有横切模式共存，产出与现有 segments 同构的数据。方案由高级工程师评估后另出文档。
