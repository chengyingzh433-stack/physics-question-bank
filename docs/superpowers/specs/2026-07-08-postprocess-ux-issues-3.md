## 1. 问题 1：已删除片段应原地显示，而非集中末尾

### 现状

后期处理页有一个「显示已删除」Switch（`PostProcessView.tsx:487`），打开后在列表末尾集中显示所有 `is_deleted=1` 的片段，**只有序号**，没有缩略图，也没有位置信息。

用户如果误删了一个片段（比如第5题中间的一段），想恢复的话需要：
- 方法 A：用 Ctrl+Z 撤销，但如果删了很久、操作了很多步之后才发现，需要很多步撤销才能回到当时的状态。
- 方法 B：在末尾的已删除区里找到那个片段恢复，但因为只有序号，很难识别到底是哪一段。

### 期望

已删除片段应该**显示在它原来的位置**上，只是用视觉方式区分（半透明、划线、灰色覆盖层等），让用户一眼就能看出"这里有个片段被删了"。效果类似邮件的"归档"而非"彻底删除"——平时不参与题目编号和排序，但还在原位可见可恢复，直到完成入库时才真正移除。

具体要求：
- 已删除片段在原位显示（与未删除片段混排，保持 page_index + order_index 顺序）。
- 已删除片段**不参与题目编号**（`derivePreviewQuestions` 里 `is_deleted=1` 的片段跳过，已实现，不用改）。
- 已删除片段视觉上明显区分（半透明/遮罩/划线），让用户一眼识别。
- 点击已删除片段可**一键恢复**（调用 `setSegmentDeleted(id, false)`，已有 IPC）。
- 「显示已删除」Switch 的语义变为：是否**显示**已删除片段的原位占位。关闭时已删除片段完全隐藏（当前行为）；打开时在原位半透明显示并可恢复。
- **入库时**，`is_deleted=1` 的片段不进入 `questions` 表（已实现，不用改），入库后它们仍在 `segments` 表但不影响任何东西。

### 涉及文件

| 文件 | 角色 |
|---|---|
| `src/renderer/src/views/PostProcessView.tsx` | 「显示已删除」Switch + 已删除片段渲染 + 入库逻辑 |
| `src/renderer/src/services/PostProcessService.ts` | `derivePreviewQuestions`（已有 is_deleted 过滤） |

## 2. 问题 2：后期处理页无法现场创建知识点/章节标签

### 现状

用户在后期处理页（`PaperReviewView.tsx`）可以给题目赋知识点、章节等标签，但只能从**已有的**选项里选。如果需要新建一个知识点或章节，必须离开当前页面，去首页的「模板管理」页（`TemplateView.tsx`）创建，再回来刷新才能选到。这个跳转打断工作流，尤其在批量入库时非常频繁。

### 期望

在后期处理页的标签选择器（Select/Chip.Group）旁边，提供一个**现场创建**入口。例如：
- 章节 Select 末尾有一个「+ 新建章节」选项，点后弹 Inline Input 输入名称，确认后调用 `createChapter` IPC 写库，即时更新下拉列表。
- 知识点 Chip.Group 旁边有一个「+ 新建」按钮，弹 Input 输入名称+可选章节归属，确认后调用 `createKnowledgePoint` IPC 写库，即时更新可选列表。

首页模板管理页的预创建功能**仍保留**，作为批量预设方案。两个入口共享同一套数据（同一张 DB 表），只是操作位置不同。

### 涉及文件

| 文件 | 角色 |
|---|---|
| `src/renderer/src/views/PaperReviewView.tsx` | 章节 Select + 知识点 Chip.Group（需加现场创建入口） |
| `src/renderer/src/views/TemplateView.tsx` | 首页预创建（保留不动） |
| `src/shared/types.ts` | `createChapter`/`createKnowledgePoint`（已有 IPC，不用改） |

## 3. 问题 3：后期处理页无法现场修改模板

### 现状

后期处理页的侧栏有模板预览下拉（`PostProcessView.tsx:476`），但只能**选择**已有模板来预览题型标注，不能编辑模板规则。如果发现模板规则不合适，需要跳到「模板管理」页修改，再回来重新选择。

同时，问题 2 提到的知识点/章节标签，在后期处理页也只能选不能创建——这与模板问题同属"工作流被打断"的痛点。

### 期望

在后期处理页（或复查页 `PaperReviewView`）提供一个**模板编辑入口**，允许用户：
- 查看当前选中模板的所有规则
- 修改/新增/删除规则（调用现有 `addRule`/`deleteRule` IPC）
- 修改后即时生效（模板预览下拉的标注自动更新）

此外，知识点/章节标签的现场创建（问题 2）也应在此处可用，两处共享交互模式。

**注意**：不需要在后期处理页重复完整的模板管理页面——只需一个轻量编辑面板（Drawer 或 Popover），列出规则列表并支持增删改即可。

### 涉及文件

| 文件 | 角色 |
|---|---|
| `src/renderer/src/views/PostProcessView.tsx` | 模板预览下拉（需加编辑入口） |
| `src/renderer/src/views/PaperReviewView.tsx` | 章节/知识点选择器（需加现场创建+模板编辑入口） |
| `src/renderer/src/views/TemplateView.tsx` | 完整模板管理页（保留不动，不在此轮改动范围） |
| `src/shared/types.ts` | `addRule`/`deleteRule`/`createTemplate`（已有 IPC） |

## 4. 问题 4：答案导入与关联（低优先级，待设计）

### 现状

当前系统只处理试卷 PDF，生成题目图片入库。没有答案相关的功能。

### 用户需求

很多试卷配套有答案 PDF（通常也是 PDF 格式），用户希望：
- 导入答案 PDF
- 将答案关联到对应题目上
- 在题库中可查看每道题的答案
- 组卷导出时可勾选「同步导出答案」

### 困难与不确定性

答案 PDF 的格式多样，可能和试卷一样需要裁切处理（一道大题的答案可能跨页、可能需要合并片段）。这意味着答案也需要走"导入→裁切→后期处理→关联"的流程，但答案和题目的**关联关系**怎么建立还不清楚：
- 是在后期处理页手动拖拽关联？
- 还是按题号自动匹配？
- 答案图片是存为题目的附属字段，还是独立的表？

用户也明确表示"这个需求不是最紧迫的"，所以本轮**不实现**，但先记录需求，后续由高级工程师设计技术方案。

### 涉及文件

- 暂无（全新功能，需新增数据模型和流程）

## 5. 红线提醒（方案设计时必须遵守）

1. **`derivePreviewQuestions` 的 is_deleted 过滤逻辑不可动**：已删除片段不参与题目编号推导，这是问题 1 的前提，也是入库逻辑的保证。
2. **入库后 is_deleted 片段仍在 DB**：不删除 segments 行，只是不入 questions 表。历史数据不能丢。
3. **现场创建标签必须走现有 IPC**：`createChapter`/`createKnowledgePoint` 已有，直接调用写库，不绕路。
4. **模板编辑不影响已有题目**：修改模板规则只影响预览标注，不改已入库题目的 type_id（除非用户手动重新套模板）。
5. **答案需求暂不实现**：只记录，不动代码。

---

## 6. 一句话总结

第三轮人测发现 4 个问题：(1) 已删除片段应原地半透明显示+可恢复，而非集中末尾；(2) 后期处理页需可现场创建知识点/章节标签；(3) 后期处理页需可现场编辑模板规则；(4) 答案导入关联（低优先级，暂不实现，先记录需求）。前三个是交互优化，核心诉求是"不打断工作流"。
