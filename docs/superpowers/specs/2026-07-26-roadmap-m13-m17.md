## 0. 总体判断

六条需求按依赖和体量排成 5 个阶段（外加一个前置收尾）。核心判断：

1. **答案功能（需求 2）是最大的一块，但不需要新造轮子**——现有 导入→裁切→片段→入库 管线可整体复用，关键是数据模型上让"答案试卷"挂到"题目试卷"下面，答案图最终落到 `questions` 行上（答案跟题走）。第三轮方案文档第 4 节已有方向性预判，本路线图细化它。
2. **年份/出处（需求 1）是小改动，先做**——既是热身，也是答案功能的前置（训练资料导出时每题要能标注来源）。
3. **全链路走一遍（需求 3）不是新功能，是验收**——放在答案功能完成后做，作为 M13+M14 的联合验收，顺便完成拖了很久的 T2 走查。
4. **PPT 导出（需求 4）独立性强、风险低**——选 `pptxgenjs`（纯 JS 生成 .pptx，无需安装 Office），每题图一页、标题文本框可编辑。放最后做功能。
5. **架构审视（需求 5）放收尾**——此时四个新功能都进来了，臃肿点看得最清楚。已知候选：PostProcessView 超 1000 行该拆、复查/后期页标签区重复 UI 该抽共享组件、`reloadAll` 里逐题查知识点是 N+1、TS6133 清理、ViewportController 抽出。

### 阶段 1（M13：题目年份 + 出处）→ ✅ 已完成（2026-07-26，待人测）

技术手册 `2026-07-26-m13-year-source-solution.md`，实现记录见进度总账 5.10。

**目标**：每道题有"年份"和"出处"（如 2023 / 新课标 I 卷），可在题库中按年份/出处筛选，导出时可标注。

**数据模型决策（已确认：试卷默认 + 单题覆盖）**：
- 年份/出处主字段挂 **`papers` 表**（`year INTEGER`、`source TEXT`，幂等迁移加列）——一份试卷的所有题默认共享年份出处。
- `questions` 加可空覆盖字段 `year_override INTEGER`、`source_override TEXT`——汇编卷里混多个来源时可单题改。
- 读取口径统一 `COALESCE(q.year_override, p.year)` / `COALESCE(q.source_override, p.source)`，筛选、题卡显示、导出标注都走这个口径。UI 上题卡默认显示继承值（淡色示"继承"），单独编辑后显示覆盖值。

**改动面**：
- `schema.ts` + `StorageService.initDatabase` 幂等迁移（照 `pages.rotation` 先例）
- `paperRepo` 读写两字段；`questionFilter.buildQuestionFilter` 加 year/source 条件（**新增条件不改现有 7 个单测的语义，补新单测**）
- `BankQuestionDTO` 加 `year`/`source`；HomeView 试卷卡片可编辑年份/出处；BankView 筛选栏加年份 Select + 出处 Select
- IPC：`papers:update` 类方法（现有若无则这是少数需要新增 IPC 的点，开工时确认）

**验收**：给试卷填年份出处 → 题库按年份筛选正确 → 题卡显示出处。

### 阶段 2（M14：答案导入 + 裁切 + 匹配）→ ⏳ 技术手册已出，待开工

细化手册见 `2026-07-26-m14-answer-solution.md`。

**目标**：题目入库后，可选进入"答案匹配"流程：导入答案 PDF → 复用裁切能力切答案 → 按题号自动匹配 + 手动微调 → 答案图入库并绑定到题目，从此答案跟题走。

**数据模型决策（默认方案）**：
- **复用 `papers` 表**：加 `kind TEXT DEFAULT 'paper'`（`'paper'|'answer'`）+ `parent_paper_id INTEGER REFERENCES papers(id)`。答案 PDF 就是一份 `kind='answer'` 的"试卷"，挂在题目试卷下。
  - 收益：`pages`/`column_dividers`/`cut_lines`/`manual_boxes`/`segments` 全部零改动复用，CropView 整个复用（路由传答案 paper id 即可）。
  - 这是整个阶段的核心杠杆——不建 `answer_papers`/`answer_segments` 平行表系（会复制一整套 CRUD/IPC/裁切逻辑）。
- **答案绑定落在 `questions` 行**：加 `answer_image_path TEXT`、`answer_width_px`、`answer_height_px`。答案图存 `projects/{题目paperId}/images/a_{questionId}.png`（`saveQuestionPng` 泛化或加薄封装）。
  - 删题级联即删绑定；导出/组卷天然能带答案——"答案一直跟着题目走"。

**新 UI：AnswerMatchView（答案匹配界面）**：
- 入口：复查页或试卷卡片上"匹配答案"按钮（仅 `status==='done'` 开放）
- 流程：导入答案 PDF（复用 ImportService）→ 裁切（复用 CropView，路由回跳）→ 匹配界面：左列题目（题号+缩略图）、右列答案片段（按 (page_index, order_index) 推导序号，复用 `derivePreviewQuestions` 思路），默认按序自动配对，支持点选改配对/一题多段答案合并
- 确认后逐题渲染答案 PNG（复用 `renderSegmentsAtDpi`/`composeQuestionCanvas`）写库

**导出**：`exportBasketPdf` 加 `includeAnswers` 开关（答案集中附在末尾"参考答案"区，每题标号对应）。

**红线预告**：现有纯函数不动；试卷状态机不动（答案 paper 有自己独立的 status 流转）；A12。

**验收**：一份真实试卷+答案 PDF 走完整流程，重启后答案仍在，删题答案图同删。

### 阶段 3（M15：全链路验收走查）

**目标**：用同一道题完整走一遍——**PDF 框选 → 存入题库（含年份/出处/题型/难度/知识点）→ 绑定答案 → 加入选题篮 → 导出训练资料（题目+参考答案）**。

- 主要是人测 + 修小问题，不预设大改动。发现的问题记成 issues 文档，走一轮小循环修掉。
- 产出：走查清单文档（每环节 ✅/❌ + 截图说明），进度总账更新。

### 阶段 4（M16：PPT 导出）

**目标**：选题篮中的题目按顺序导出为 .pptx，每题一页，可编辑。

**技术决策（默认方案）**：
- 用 **`pptxgenjs`**（纯 JS、无需 Office、主进程可跑）。新增依赖（需确认接受）。
- 每页：题号标题（可编辑文本框）+ 题图（等比缩放居中，图片对象可移动缩放）+ 可选出处角标；答案可选：附在同页下方 / 紧跟一页 / 不带。
- BasketView 导出按钮旁加"导出 PPT"，IPC 新增 `export:basketPptx`（这是明确需要新增 IPC 的点）。

**验收**：导出的 pptx 在 WPS/PowerPoint 中打开，逐页题图清晰、文本框可编辑、顺序与篮内一致。

## 2. 执行约定（贯穿所有阶段）

1. **一阶段一循环**：开工前出该阶段细化技术手册（`-solution.md`），完成后更新进度总账 + 写明下一阶段计划，然后才动下一阶段。
2. **每阶段独立自测**：typecheck + build + 单测全绿 + 用户人测通过才算完。
3. **数据库只加不改**：所有 schema 变更走幂等迁移（`PRAGMA table_info` 检查后 ALTER TABLE 加列/建表），老库直接升级不丢数据。
4. **纯函数红线延续**：`derivePreviewQuestions`/`derivePreviewItems`/`deriveSegments`/`deriveAllSegments`/`applyTemplate`/`buildQuestionFilter` 签名语义不动（buildQuestionFilter 阶段 1 加条件属于扩展，补单测不改旧测）。
5. **新增 IPC 集中申报**：阶段 1 的 `papers:update`、阶段 2 的答案相关、阶段 4 的 `export:basketPptx`——每阶段手册里列清单，不散加。

## 3. 已确认的决策（2026-07-26 用户拍板）

1. **年份/出处：试卷默认 + 单题覆盖**——`papers` 加 `year`/`source`，`questions` 加可空覆盖字段（如 `year_override`/`source_override`），显示与筛选时 `COALESCE(题覆盖, 卷默认)`。比纯挂试卷多一层逻辑，阶段 1 手册里给清楚 COALESCE 的读取口径和 UI（题卡默认显示继承值、可单独改）。
2. **答案数据模型：复用 papers 表**（`kind`+`parent_paper_id`，裁切界面完全复用）。
3. **PPT 导出：pptxgenjs**（新增 npm 依赖）。
4. **PDF 导出答案位置：导出时三选**（末尾集中 / 每题紧跟 / 不带），导出对话框加选项。

## 4. 一句话总结

先小后大：M13 年份出处（热身+前置）→ M14 答案匹配（最大块，杠杆是复用 papers 表和整条裁切管线）→ M15 用同一道题走全链路验收 → M16 PPT 导出（pptxgenjs 每题一页）→ M17 架构减脂。每阶段一轮循环、一份手册、一次进度总账更新，做完当前阶段再规划下一步。
