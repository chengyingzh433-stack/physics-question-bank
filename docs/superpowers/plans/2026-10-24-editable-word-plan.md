# 下一阶段开发方案：可编辑题目与 Word 组卷（M18）

日期：2026-10-24。基线：Mac beta.4。交付目标：beta.5，供用户自行功能验收。

## 1. 这次做什么

下一大模块是**可编辑题目与 Word 导出**。完成从题库打开题目、对照原图编辑题干和答案、保存历史、回到组卷篮排版、导出可继续修改的 DOCX 的完整流程。

用户最新开发准则已写入根目录 [AGENTS.md](../../../AGENTS.md)：不编写、不运行冒烟测试、自动化功能测试或界面走查脚本；功能测试交给用户。开发者只完成实现、静态审查、类型检查、编译与安装包制作，交付用户操作清单。旧文档中的“先跑回归再开发”等要求不再是本阶段前置。

## 2. 为什么先做这个模块

已有流程能导入 PDF、裁题、存图、归类、选题和导出图片式 PDF/PPT，但每题只是一张图，教师不能直接修改题干数字或公式。本阶段补齐可编辑内容的存储和输出，让后续识别引擎有可落地的结果接收位置。

本阶段从人工输入或粘贴文字开始，配图可以直接从原题图裁取。不会把扫描图片声称为已自动转成文字，也不会要求先购买识别服务。OCR 放在这一流程交付之后，避免识别选型与编辑交付互相阻塞。

## 3. 借鉴的成熟方案及选择

本轮重新查阅官方来源，采用成熟组件而不自行实现富文本编辑器、数学排版引擎或 TeX 解析器。

| 来源 | 借鉴 / 使用方式 | 本项目边界 |
| --- | --- | --- |
| [Doc2X 教师题库官方教程](https://doc2x.noedgeai.com/help/en/tutorials/teacher-question-bank.html) | 借鉴对照校对、题库积累、选题组卷、编辑教学材料及 Word 输出流程 | 独立 Web 产品；本项目未接入其云识别 API |
| [Doc2X MCP](https://github.com/NoEdgeAI/doc2x-mcp) | 澄清此前“参考开源项目”的记忆 | 开源的是接入工具，不能据此认为整套教师题库开放源码 |
| [Tiptap React](https://tiptap.dev/docs/editor/getting-started/install/react) | 3.32.0，处理文字、选区、撤销重做、粘贴与扩展节点 | 使用开源核心，限定可完整保存及导出的段落、粗体、斜体、换行、公式与图片 |
| [MathLive](https://mathlive.io/mathfield/guides/integration/) | 0.111.1，可视数学输入与 LaTeX 表达；字体随包 | 离线编辑，不调用 CDN、不上传题目 |
| [docx.js](https://docx.js.org/api/) | 9.14.0，创建 Word 段落、图片、页边距与文档结构 | 输出 DOCX，不承担打开和无损还原任意 Word 文件 |
| [mathml2omml](https://github.com/fiduswriter/mathml2omml) | 0.5.0，将 MathLive 生成的 MathML 转成 Word 原生公式 | 独立依赖保留 LGPL 许可与源码；不支持的公式明确报错，不静默删掉或变图片 |
| [saxes](https://github.com/lddubeau/saxes) | 6.0.0，严格检查转换中的 XML 结构 | 用于生成流程校验；项目已归档，后续升级时复核维护状态 |

先前调研提出 Pandoc，本阶段改用上述本地 JavaScript 组合：它可直接随 Electron 安装包提供，避免 Mac/Windows 用户额外安装 Pandoc。此选择是部署与集成判断，不代表已经通过 Word/WPS 功能验收。

## 4. 用户流程

1. 在“题库浏览”的卡片或预览中点击“编辑题目与答案”，组卷篮也有相同入口。
2. 对照原始题图，分别编辑题干和参考答案；原图始终保留。
3. 输入或粘贴文字，使用公式编辑窗口录入数学内容；导入 PNG/JPEG 或框选原图中的物理配图。
4. 调整配图宽度、对齐和图注；每个部分分别选择 Word 使用原图还是已编辑内容。
5. 保存版本；之后可以继续编辑、查看历史或恢复某次保存的内容。恢复本身生成新版本。
6. 在组卷篮调整题序、分组标题、题号、标题和副标题；设置字号、页边距、题后留白、答案位置及是否逐题新页。
7. 预览内容后导出 Word。原图题和可编辑题可以混排；可编辑题中的文字、公式、图片保留各自结构。

## 5. 数据与失败处理

- 原 questions 行、原 PDF、题图、答案图保持原有存储语义。
- 新增 question_contents 存当前内容；question_content_revisions 记录每次保存；question_assets 记录本题独立配图。
- 内容采用受限 JSON，不保存任意 HTML、外部图片 URL 或机器绝对路径。公式保存 LaTeX；配图只引用本题资产 ID。
- 保存时校验文档结构、长度、配图归属、空内容与版本号；并发修改产生明确冲突，避免静默覆盖。
- 图片统一保存 PNG，文件名唯一且不可变，移除某次正文中的图片不删除历史版本仍可能引用的文件。
- Word 导出以保存的内容为准，读取当前组卷快照；错误指出题目和出错内容，取消保存不写文件。
- 无可编辑版本的旧题保持原图模式，新增表采用幂等建表兼容旧库。原图/答案重新裁切不覆盖已保存的编辑版本，需由用户核对是否同步修改。

## 6. 本阶段包含与不包含

包含：题干/答案编辑、可视公式、独立配图导入/裁图/缩放、历史版本、原图与编辑内容混排、Word 组卷排版设置与预览、DOCX 原生公式输出、Mac 安装包。

边界：

- 不包含 OCR 自动识别、Word 导入、表格编辑、完整 Office 式分页编辑器。
- 配图仍为图片，不把电路图每条线或扫描图中的字变成独立对象。
- 内容预览显示 A4 内容宽度与阅读顺序；实际换行和分页由 Word/WPS 决定，不能宣称逐像素一致。
- 旧 PDF/PPT 导出继续使用原始题图和原始答案图；编辑后的内容由 Word 输出，需 PDF 时可由 Word/WPS 另存。
- 未提供 Apple Developer ID 签名和公证，Mac 安装包面向 Apple Silicon；Windows 新模块功能验收仍待用户执行。

## 7. 实施与交付顺序

1. 固定共享文档格式和开发准则。
2. 实现本地内容、图片和追加式历史存储。
3. 接入 Tiptap / MathLive 的对照编辑页。
4. 完成 Word 原生公式转换与排版生成。
5. 将编辑入口、组卷设置、预览和导出连成完整流程。
6. 只进行静态审查、类型检查和编译，制作 DMG，附用户验收清单。交付记录将明确功能验收未执行。
