**Goal:** 在保留已有题库和现有工作流的基础上，确认 M17 后的真实状态，补齐验证与交付缺口，形成可持续维护的 Windows 版本。

## 9. 维护原则与范围控制

- 以数据库为持久化真值，遵守先写库、再更新界面；几何坐标继续使用比例坐标。
- 答案卷继续复用 papers/pages/segments 流程，通过 `kind/parent_paper_id` 与题目卷隔离；不要新建一套重复裁切管线。
- 变更旧库时使用幂等迁移并验证副本；不要为新功能清空真实题库。
- 不把 OCR、Word 导入导出、云同步、多设备、学生端、学情分析等原始远期设想计入本轮欠账。
- PPT 的“可编辑”只覆盖文本框和图片对象；公式、题干正文仍是图片。
- 每次完成一阶段，同时更新日志中的当前状态、验证证据和剩余事项。新日志分别列“代码完成”“自动检查”“人工验收”“安装交付”，不再用一个完成标记覆盖全部。

**建议第一轮实际开发目标：完成 Task 1–4，将当前功能变成数据可恢复、导出可验证、安装版与源码一致的可交付版本。** Task 5–6 排在其后，根据实测表现和使用需求推进。
