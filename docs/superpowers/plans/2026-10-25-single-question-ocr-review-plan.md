# 单题识别与校对开发方案

日期：2026-10-25。阶段：M19。基线：已发布的 Mac 1.1.0-beta.5。状态：用户已于 2026-10-25 确认优先接入 Doc2X，按下述范围实施。MinerU 仅保留为后续备选。实际交付和验收边界见 [M19 交付记录](../specs/2026-10-25-doc2x-ocr-delivery.md)。

下一阶段解决“每道题还要手工输入文字和公式”的问题：把现有题图或答案图生成可编辑候选稿，经过人工校对后，保存到题库并沿用现有 Word 组卷功能。

**建议首版接入可选的 Doc2X 单图云识别，完成单题识别、校对、采用和保存的完整流程；MinerU 本地识别作为替代路线供本次审阅选择。** 默认关闭云识别，不自动上传题库。首版不同时交付两套识别引擎，也不把整卷批处理、Word 导入或表格编辑混入本阶段。

## 1 本次需要审阅的选择

| 事项 | 建议方案 | 另一选择及影响 |
| --- | --- | --- |
| 首个识别引擎 | Doc2X 可选云服务，用户自行配置 API Key 和额度 | MinerU 本地识别，题图不出本机，但需增加模型下载、独立运行环境和本地服务管理 |
| 识别范围 | 从现有题目编辑页发起，只识别当前题干或答案图 | 整卷或题夹批量识别放到后续，避免首版同时承担批量费用和结果管理 |
| 配图和复杂表格 | 有有效图片资源就独立保留；缺失时提示并允许从原图裁取 | 自动重建所有表格、还原每条图形线条不列入首版 |
| 内容生效方式 | 识别结果先保存为候选，用户校对、采用并保存后才进入正式版本 | 不自动覆盖已有题干、答案或导出模式 |

同意这份方案开发，只确定功能范围；实际上传仍由用户在应用内启用云识别并点击识别触发。本轮审阅不需要提供密钥或上传试卷。

## 2 已有基础和成熟方案选择

beta.5 已实现题干和答案编辑、公式输入、独立配图、历史版本和 Word 导出。M19 继续使用 Electron、React、SQLite、Tiptap 和 MathLive，不重新开发编辑器。beta.5 的功能验收仍由用户执行；若反馈出现保存或导出的阻断问题，先修复相关问题，不增加开发者自动功能测试关卡。

Doc2X 教师题库的公开流程可继续作为校对与组卷参考；公开的 doc2x-mcp 是 API 接入工具，不能据此把整套产品或识别引擎视为开源。[教师题库教程](https://doc2x.noedgeai.com/help/en/tutorials/teacher-question-bank.html)、[MCP 仓库](https://github.com/NoEdgeAI/doc2x-mcp)。

| 路线 | 已知条件 | 本项目的判断 |
| --- | --- | --- |
| Doc2X 单图接口 | 接收 JPG/PNG，支持异步任务；返回 Markdown 和可选图片包。需要 API Key 及解析额度 | 可直接接入当前桌面应用，减少本机环境安装工作，因此建议首版优先；识别效果由用户用实题验收 |
| MinerU 本地识别 | 官方提供 macOS 路线、结构化输出及本地服务；需要单独安装运行环境和下载模型 | 保留为优先本地的替代路线；若用户选择它，首版任务需加入组件安装、更新和资源占用管理 |

这台 Mac 为 Apple M5、16 GiB 内存。MinerU 官方列有 Apple Silicon 运行路线，但不能从硬件条件推断本机识别速度或准确率。选择本地路线时，交付目标仍是应用内操作，不要求日常使用命令行。[MinerU 官方说明](https://github.com/opendatalab/MinerU)。

单图接口不能假定提供逐块坐标；Doc2X 的 `layout.blocks`、图形地址与表格结构属于另一个 PDF v3 流程。首版按真实返回字段处理，不承诺自动定位每一处识别错误或缺图。[图片接口](https://doc2x.noedgeai.com/help/zh-cn/api/doc2x-api-v2-image-interface.html)、[v3 JSON 说明](https://doc2x.noedgeai.com/help/en/api/doc2x-api-v3-json.html)。

## 3 用户实际操作流程

1. 从题库或组卷篮进入“编辑题目与答案”，选择“题干”或“答案与解析”。
2. 点击“识别当前原图”。第一次使用先选择识别服务并填写配置。没有答案图时说明原因，继续允许手工输入答案。
3. 显示本次要处理的图片、识别对象和服务名称。可选择整张题图，也可框选其中一部分；云服务只上传这次确认的图片副本。
4. 发起后显示“提交中”“识别中”“已返回，待校对”等状态。等待期间可以继续编辑当前稿。
5. 结果进入“识别候选”标签。左侧看原图，右侧在当前稿和候选稿之间切换；候选中的文字、公式和图片可校正。
6. 点击“采用到编辑稿”，选择“替换当前部分”或“追加到当前部分”。替换前保存完整恢复草稿；另一部分内容保持不变。
7. 校对完成后保存。若想在 Word 中使用，明确选择该部分的“可编辑内容”模式。之后继续按现有组卷流程导出。

首次交付在编辑页内增加这些操作，不另外做一套识别网站或全新主导航。

## 4 开发任务和具体细则

| 任务 | 必须完成的行为 | 交付标准 |
| --- | --- | --- |
| M19 01 识别配置 | 可启用、停用、更新和清除服务配置；未配置时给出设置入口；凭据不出现在普通日志和仓库 | 不配置识别也能继续使用 beta.5 的编辑和导出功能 |
| M19 02 输入准备 | 分清题干和答案；整图或用户选区生成临时副本；显示体积；保留原图和原 PDF | 不改原件，不把整份试卷或其他题目一起上传 |
| M19 03 任务执行 | 提交一次、记录任务号、查询状态；保存明确错误；首版同一时刻只提交一个识别任务 | 界面能离开再回来；不会因重复点击或查询重试重复创建任务 |
| M19 04 结果转换 | 用成熟 Markdown 解析组件处理文字与数学表达；转换到现有受限文档；图片落为本题独立资源 | 不把原始 HTML 直接当界面执行，不引用临时外链作为长期题库资源 |
| M19 05 对照校对 | 原图、当前稿和候选稿可切换比较；沿用文字、公式及图片编辑操作 | 用户可修正后再采用；识别质量分不能代替“已校对”状态 |
| M19 06 采用与保护 | 替换或追加仅针对所选部分；采用前持久化完整恢复草稿；校验题目、原图和版本未发生冲突 | 识别期间的新编辑不被迟到结果覆盖；采用错误可以找回原稿 |
| M19 07 异常与恢复 | 支持停止本地等待、继续查询、明确重新识别；重开后保留任务和候选 | 网络失败、余额不足、结果过期或取消均不损坏原稿 |
| M19 08 状态与整理 | 分别显示任务进度、校对状态和采用状态；候选可丢弃；保留必要来源记录 | 区分“已加入编辑稿”和“已保存到题库”，不将“返回结果”显示成“内容正确” |
| M19 09 完整交付 | 更新操作说明和用户验收清单，完成静态审查、类型检查、编译及 Mac DMG | 交付可供用户验收的完整模块，记录真实完成状态 |

这些任务是内部实施顺序，最终统一交付；不以只有按钮、返回原始文本或单独演示接口作为本阶段完成。

## 5 内容转换和原稿保护规则

**文字与公式。** 保持题干、选项及解析的阅读顺序。能转换的数学表达成为现有可编辑公式；不能转换的表达保留原始识别文本并显示待处理提示，不删除、不猜写正确答案。显示公式可放入单独段落，沿用现有文档格式。

**配图。** 服务返回图片包且引用有效时，将配图保存到本题资源目录。图片缺失或包损坏时，保留相应提示及原图对照，提供人工裁图入口。没有可靠位置就不自动裁剪，也不从文件名猜出坐标。

**表格。** 现有编辑器没有表格节点，首版不把表格拆成可能错位的普通段落。若没有可直接保留的表格图片，提示用户从原图裁取后插入；未处理前可以保留候选，正式采用时必须明确处理方式，不能静默省略表格。

**候选留存。** 除转换后的正文，另存原始识别 Markdown、待处理事项和用户处理决定。表格、缺图、转换错误不能仅靠编辑器正文表示；重开候选时仍需显示未解决事项，不能因为转换失败而丢失原始内容。

**校对状态。** 用户完成核对才可标记为已校对。后续修改应标记为“已修改，待复核”。没有可靠逐块置信度时不编造错误高亮或百分比准确率。

**采用与保存。** 候选、恢复草稿和正式版本分开存储。采用前保存的恢复草稿应包含尚未保存的题干、答案和导出模式，允许保留尚未完成的编辑状态；它不冒充已通过内容校验的正式版本。恢复草稿先回到未保存编辑态，用户完善并保存后才生成正式版本；恢复正式历史版本仍生成新版本。候选加入编辑稿后标为“已加入编辑稿”；正式保存成功才标为“已保存到题库”并关联版本号，放弃编辑或恢复旧版时同步更新状态。

**来源变化。** 任务绑定题目、题干或答案、原图指纹、选区、发起时正式版本和当前草稿标识。正式版本号不足以发现未保存的修改，采用时还需比较草稿标识。识别期间换了答案图、重新裁题、删除了题目，或当前稿有新修改，结果不得直接写回；保留可用候选并提示重新确认。已删除题目的迟到结果不能复活题目。

## 6 网络、费用和恢复细则

Doc2X 图片接口目前限制请求体不超过 7 MiB，每张图片消耗一页解析额度；实际金额和账户限制以开放平台为准。题干和答案分别提交即分别消耗额度，不显示没有依据的价格估算。[官方图片接口](https://doc2x.noedgeai.com/help/zh-cn/api/doc2x-api-v2-image-interface.html)。

- 默认不自动批量识别、不自动切换其他供应商，也不自动购买额度。
- 图片超限时提示调整选区或生成较小副本，并展示待提交副本；不覆盖原图，不无限压缩直到公式难以辨认。
- 发起请求后保存任务号。查询失败优先续查原任务；不得用重复提交充当重试。
- 提交超时且拿不到任务号时标记“提交状态不明”，提示可能已创建任务，等待用户决定是否再次提交。
- 停止本地等待不声称已经取消远端任务或退费。停止后的响应不能自动采用。
- 服务端结果保留时间有限，完成后保存本地候选与有效图片；重新打开优先读取本地副本。结果过期后提示重新识别，由用户决定是否再次消耗额度。
- 同一图片已有候选时提供“查看已有结果”与“重新识别”；已有内容在新任务失败后仍保留。

凭据只由主进程发起请求时使用；若选择本机保存，使用操作系统支持的安全存储，不能明文放入通用设置表。当前 Mac 包未签名，系统可能在更新后再次请求凭据访问权限；不可用时允许用户重新输入，不退回明文保存。[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。

## 7 实施顺序和交付边界

| 顺序 | 工作 | 产生的结果 |
| --- | --- | --- |
| 1 | 用户审阅识别路线与首版范围；整理 beta.5 已反馈的阻断问题 | 明确采用 Doc2X 或本地替代路线 |
| 2 | 接入配置、输入副本、任务记录和结果适配 | 能将一次识别结果保存为独立候选 |
| 3 | 接入校对、配图补全、采用前恢复草稿和版本保护 | 从原图到正式可编辑题目的完整操作流程 |
| 4 | 补齐失败、取消、重开、来源变化和重复提交处理 | 可恢复的任务与内容状态 |
| 5 | 开发者做静态检查和构建，制作 DMG 与说明 | 交由用户执行功能验收 |

实施完成后的交付物为完整功能代码、操作说明、用户自测清单、实际检查记录，以及上传到本仓库 GitHub Releases 的 Apple Silicon Mac DMG。继续保持 Windows 的路径、快捷键、文件选择和存储兼容；未制作或未验收的平台安装包不能标为已通过。用户已授权本阶段完整实现、制作 Mac DMG 并上传 GitHub；实际结果以交付记录为准。

首版不包含整卷自动切题、题夹批量 OCR、多个识别引擎同时维护、自动生成答案、公式自动判对、Word 导入、可编辑表格、物理图形矢量重绘、全题库全文搜索或完整资料迁移。这些能力不影响当前单题流程交付，可根据使用反馈后续安排。

## 8 用户验收清单

按 [项目开发准则](../../../AGENTS.md)，开发者不编写、不运行冒烟测试、自动化功能测试、界面走查脚本或打包程序功能测试。开发者负责实现、静态审查、类型检查、编译和安装包；以下功能验收全部交给用户。

建议用户选择约 12 道实际题目，包含清晰题图、扫描题、公式密集题及图表混排题，并带几道参考答案。记录错字、公式结构、漏图和校对耗时，用于决定识别路线是否值得继续使用；本阶段不预先设定模型准确率或识别秒数承诺。

- [ ] 未启用识别时，原有编辑、保存和 Word 导出仍可使用。
- [ ] 题干与答案分别识别，所处理的图片和对象正确；没有答案图时不误用题干。
- [ ] 文字、选项、分式、上下标和物理符号可校对，不能转换的内容有提示。
- [ ] 配图完整保留；缺图或复杂表格能够手工裁取补全，不静默遗漏。
- [ ] 等待识别时继续修改正文，结果返回后仍能保留新修改。
- [ ] 替换和追加只改变所选部分，另一部分及导出模式符合用户选择。
- [ ] 采用错误后可恢复之前未保存的整题草稿，正式历史版本也仍可找回。
- [ ] 取消、断网、凭据或额度错误不会损坏原稿；重开能找到已保存候选。
- [ ] 保存并选用编辑内容后，组卷顺序、参考答案和 Word 中的文字、公式、配图符合预期。
- [ ] 题目来源已改变时不会自动错用旧结果，失败后可明确重试或继续人工编辑。

## 9 实现落点

本节供后续开发使用，保持现有架构。

- 主进程新增识别服务适配层、任务管理及凭据存储，渲染层只调用类型化 IPC。
- 新增任务、候选和恢复草稿记录；记录服务、远端任务号、目标部分、原图指纹、发起版本、草稿标识、状态和错误，不记录明文密钥。候选另存原始 Markdown、转换后的正文、待处理事项及处理决定。
- 结果统一转换成现有 `EditableDocument`，配图复用 `question_assets`，正式保存复用版本校验与历史记录。
- 校对标记及识别来源按题干、答案分别记录，并随正式版本保留，避免恢复旧版后出现错误的“已校对”标记。
- 结果图片包按本地资源导入：限制大小与解包路径，只接收受支持图片；不加载候选中的任意外部地址。
- 清理任务或临时文件前检查当前稿、候选、恢复草稿和历史版本的引用。Mac 与 Windows 使用平台路径和系统凭据机制。

选择 MinerU 本地路线时，以上内容和流程仍复用，但在第 2 步增加独立识别组件的安装、模型管理、启动停止与异常退出处理。模型不直接塞进主应用 DMG，不静默改用云服务；本地路线的安装与运行细则另补齐后再实施。
