# M21 多来源录题工作台方案

日期：2026-10-25。基线：1.1.0-beta.7。用户已确认同时需要原稿框选和分区粘贴两种方式。本阶段实现后交付 Mac DMG，功能验收由用户完成。

## 本阶段的大功能

新增“录题工作台”，把截图、剪贴板图片、PNG/JPEG、PDF 和 Word（DOCX）统一变为一道题的录入草稿。左侧查看原稿、翻页并框选，右侧添加题干、选项、答案、解析和配图；也可以直接粘贴文字或图片，调整顺序后进入已有的 Doc2X 识别与人工校对页。确认完成才进入题库与组卷流程。

## 操作与交付范围

1. 新建录题草稿；文件选择或拖入多个原稿，或通过按钮、⌘V/Ctrl+V 粘贴截图。文字在对应输入框内正常粘贴。图片可作为原稿框选，也可直接加入当前部分。
2. PNG/JPEG 查看整图，PDF 按页渲染，DOCX 在本机预览；原件独立留存。旧 DOC 明确提示先另存 DOCX 或 PDF。
3. 选择题干、选项（标记 A/B 等）、答案、解析、题干配图或答案配图。框选产生独立图片副本；直接输入保留文字。允许混用、删除组件和调整顺序。
4. 保存草稿并可恢复。一次组成一道题，可重复利用同一份原稿继续录下一题。原稿和组件不随删除组件而销毁。
5. 组题时生成题干、答案的本地预览图，直接输入的文字与独立图片同时成为初始可编辑稿。进入统一校对页后按需使用 Doc2X；每次上传仍显示待提交图片并要求确认。没有密钥也能手工完成。
6. 组题快照冻结；需要重组时复制成新草稿，保留原稿、旧快照和识别记录。校对页保存后，用户勾选确认并入库。正式题目继续使用现有编辑、历史版本、题夹和 Word 导出。

## 数据与成熟方案

- 沿用 Electron、React、SQLite、PDF.js、现有 Doc2X 图片接口、Tiptap、MathLive 和内容版本系统。
- DOCX 使用 [docx-preview](https://github.com/VolodymyrBaydalka/docxjs)，局部渲染采用 [html-to-image](https://github.com/bubkoo/html-to-image)。记录版本与许可。Word 预览不依赖安装 Office、LibreOffice 或系统转换命令。
- 新增原稿登记、草稿及组件资源表。图片和文档保存在现有可迁移的项目目录中；原件不可覆盖。未发布草稿不出现在题库或旧 PDF 裁题列表。
- 主进程限制文件类型、体积、解压大小、图片尺寸与资源归属；草稿修改使用版本检查。DOCX 预览移除外部资源关系、拒绝宏与活动内容，并关闭 HTML 嵌入；不会因预览联网取图。
- 导入和预览默认全在本机。只有用户确认的单题图或答案图发送 Doc2X；不会自动上传整份 PDF/Word。

## 边界

- DOCX 的复杂浮动对象、旧公式、分页和特殊字体可能与 Word 不同；预览失败或不准确时可改用 PDF/截图，原文件仍保留。不支持旧 DOC、加密 Word、宏文件；不承诺无损复原所有 Word 版式。
- 每次由用户选定并组合一道题，不自动分割整卷、不批量消耗云额度。识别为文字/公式转换，物理答案正确性仍由用户判断。
- 配图和复杂表格可作为图像保留；选项标签在组题草稿中独立维护，保存后按顺序进入现有正文模型。

## 开发与验收准则

不编写、不运行冒烟测试、自动化功能测试、界面走查或打包应用功能测试。仅做代码审查、类型检查、编译和安装包制作；不得把这些称为功能测试通过。macOS 优先，文件路径、文件选择与快捷键兼顾 Windows。交付另附操作步骤、用户自测清单、依赖与已知边界，并同步进度文档和 GitHub 发布。
