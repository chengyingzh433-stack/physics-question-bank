# M23 单题录入流程修复方案

## 依据与范围

本机 beta.9 实际界面体验发现：首页只引导旧 PDF 裁切；录题首屏被说明和标签占据；图片编辑稿没有明确区分图片与文字；切换答案时抛出 `Cannot read properties of undefined (reading 'some')`，重试后未保存文字和标签丢失；入库后仍停在编辑页。

本阶段完成一条清楚的单题路线：**选择原稿 → 校对题目、补答案、选标签 → 保存入库**。保留原稿及现有组卷、分区组题能力，不新增批量录题。

## 实施

1. 修复空文档兼容：接收、编辑、预览及内容判断统一处理空文档；编辑器启用状态改变不能产生正文修改。空答案可编辑；输入答案后自动使用编辑内容。
2. 保存未提交编辑的本机恢复副本（题干、答案、标签、基础版本）。页面重试可恢复；正式版本变化时提示确认，不悄悄覆盖新内容；正式保存成功后清理副本。保存失败或存储空间不足明确提示。
3. 打开软件即显示统一录题入口，支持选择图片/PDF/DOCX、粘贴、直接输入文字、拖入文件；主导航收敛为录题、题库、组卷。旧整卷裁切及模板放到辅助入口。
4. 校对首屏先展示原稿和正文；去掉重复的大段说明。题干/答案切换明确，图片状态明确提示“尚未转成文字”，识别入口靠近正文。标签在正文之后可直接填写；导出设置收起。
5. “保存并入库”作为最终确认动作；成功后明确显示完成状态、题卡预览、“查看题库”和“继续录下一题”。不再让用户猜是否完成。
6. 发布 beta.10，更新本机应用，上传 GitHub Mac DMG，并同步交付说明。

## 验证边界

用户本次明确要求的真实界面操作已发现上述问题；修复后仅针对本次录题路径进行人工界面复核。不编写或运行冒烟测试、自动化功能测试、界面走查脚本或历史功能测试套件。另做类型检查、静态审查、编译与安装包校验，分别记录证据。Doc2X 本机尚无 API Key，不宣称云识别验收通过；不上传用户原稿。

## 用户验收

从打开软件开始导入一张题图，切换答案并输入，选择题型/标签，保存后查看题卡；尝试 PDF/Word 选区进入同一个校对页；关闭/重进未保存编辑查看恢复提示。原稿、原题图及已有题目不应改变。
